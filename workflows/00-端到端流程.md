# 新建主题流程（端到端标准）

## 完整流程概览

```
生图 → 配色 → 编辑pen → Pencil确认？→ 导出素材 → 验证素材 → YAML配置 → 打包 → 验证输出
```

---

## Step 1: 生成主题背景图

**工具**: MiniMax Image API

```bash
source .env
curl -s -X POST "https://api.minimaxi.com/v1/image_generation" \
  -H "Authorization: Bearer $MINIMAX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "image-01",
    "prompt": "{场景+元素+风格+约束}",
    "aspect_ratio": "16:9",
    "response_format": "base64",
    "n": 1
  }' | python3 -c "
import sys, base64, json
data = json.load(sys.stdin)
img_data = data['data']['image_base64'][0]
with open('designs/{nameEn}-bg.png', 'wb') as f:
    f.write(base64.b64decode(img_data))
print('OK')
"
```

**Prompt 规则**:
- 描述场景主体（如：大象、孔雀、热带植物）
- 描述氛围（如：温暖阳光、明亮活泼）
- 必须包含："no text", "no UI elements", "pure atmospheric illustration"

**输出**: `designs/{nameEn}-bg.png`

```bash
import json, colorsys

def calc_colors(p):
    # White mix, darken, lighten, desaturate 等计算
    ...

scheme = {"name": "...", "nameEn": "...", "colors": {...}}
with open("colors/{nameEn}.json", "w") as f:
    json.dump(scheme, f, indent=2)
EOF
```

**Light-UI 计算规则**：
```
primaryHover = primary + 亮度（+10-15%）
alterColor = primary - 亮度 + 降饱和（-15%亮度，-20%饱和）
alterColorHoverOn = primaryHover + 亮度（+10%）
opacity10/20/30 = primary + 白色混合（10%/20%/30% 透明度）
```

**输出**: `colors/{nameEn}.json`

## Step 3: 复制模板 → 用脚本自动替换

```bash
# 复制模板
cp "designs/sources/Light-UI-模板.pen" "designs/Topic-{主题名}-{timestamp}.pen"

# 自动替换（6项更新）
python3 scripts/update-pen-theme.py {nameEn}
```

**脚本自动完成**：
1. 替换框架名称（【示例名】→【新主题名】，跳过"勿删除"）
2. 更新所有 color variables
3. 更新 text content 中的硬编码色值
4. 更新渐变组件（只改 RWYIx + 6U9v0，不动其他）
5. 替换登录页背景图（绝对路径，匹配所有旧路径模式）
6. 替换页眉/工作台背景图

**关键约束**：
- 脚本使用硬编码模板默认值构建色值映射（不读 pen 文件）
- 图片路径使用绝对路径

**输出**: 更新后的 `designs/Topic-{主题名}-{timestamp}.pen`

---

## Step 4: 🚧 打开 Pencil 等待确认

```bash
open -a Pencil "designs/Topic-{主题名}-{timestamp}.pen"
```

**必须等待用户确认** → 用户说"可以"才进入下一步。

**禁止**：Pencil 打开后自动继续，任何自动继续都是错误。

## Step 5: 导出素材节点 + ImageMagick 裁剪

```bash
# 5.1 从 Pencil 导出节点
# pencil_export_nodes → A7bgM, TdfhH, C0kVM, Nk9d0, jTA4O, LiN3g, nXv3Y, dKOHu

cd "output/{date}-{主题名}/素材包"

# 5.2 裁剪调整（ImageMagick）
cp LiN3g.jpeg bg-login.jpg
convert bg-login.jpg -crop 1920x1080+147+0 +repage background.png
convert nXv3Y.jpeg -resize 960x540\! login_thumb.jpg
convert bg-login.jpg -crop 800x390+0+345 +repage login_bg/thumb-1.jpg
convert bg-login.jpg -crop 800x390+800+345 +repage login_bg/thumb-2.jpg
convert Nk9d0.png -crop 2560x480+0+30 +repage header-banner.png
convert dKOHu.png -resize 1440x800\! desktop.png
convert dKOHu.png -resize 1600x572\! layout-banner.jpg
# ... 复制页眉背景（无需裁剪）
```

**输出**: 素材包（17个文件）

## Step 6: 🚧 验证素材完整性

```bash
cd "output/{date}-{主题名}/素材包" && python3 << 'EOF'
from PIL import Image
import os

files = {
    'bg-login.jpg': (2215, 1080),
    'login_thumb.jpg': (960, 540),
    'header-banner.png': (2560, 480),
    'header_tlayout_frame_bg.png': (1920, 60),
    'header_complex_frame_bg.png': (1920, 90),
    'header_menu_frame_bg.png': (1920, 130),
    'header-sideheader.png': (200, 900),
    'header_single_menu_frame_bg.png': (200, 900),
    'desktop.png': (1440, 800),
    'layout-banner.jpg': (1600, 572),
    'login_bg/thumb-1.jpg': (800, 390),
    'login_bg/thumb-2.jpg': (800, 390),
    # ... 其他文件
}

missing = 0
for fname, (ew, eh) in files.items():
    if not os.path.exists(fname):
        print(f'❌ 缺失: {fname}')
        missing += 1
        continue
    w, h = Image.open(fname).size
    status = '✅' if w == ew and h == eh else '❌'
    if w != ew or h != eh: missing += 1
    print(f'{status} {fname}: {w}x{h}')

print(f'\n结果: {len(files)-missing}/{len(files)} 通过')
exit(1 if missing > 0 else 0)
EOF
```

**验证失败 → STOP，修复后重试，不能跳过。**

## Step 9: 🚧 验证输出包

```bash
cd "output/{date}-{主题名}/输出包"

# 9.1 检查 zip 数量
echo "=== ZIP COUNT ===" && ls *.zip | wc -l
# 应输出: 15

# 9.2 验证颜色注入（抽检一个 V 系列包）
echo "=== COLOR INJECTION ==="
unzip -o -q '主题-V14〜V16-*.zip' -d /tmp/verify
find /tmp/verify -name "*.css" -path "*/style/*" -exec cat {} \; | \
  grep -oE '#[0-9a-fA-F]{6}' | sort | uniq -c | sort -rn | head -3
rm -rf /tmp/verify
# 主色（如 #F5C542）应该是出现次数最多的
```

**验收标准**：
- ✅ 15 个 zip 生成
- ✅ CSS 中主色出现次数 ≥ 100 次（确认注入生效）
- ✅ 无旧模板色值（旧主色如 #2C615C 出现 0 次）
- ✅ MK 包的 style.css 和 simple.css 都注入了新色值

**失败 → STOP，修复后重新打包。**

## 关键修复记录

| 问题 | 根本原因 | 修复 |
|------|----------|------|
| V12/V13 登录包丢失根文件 | `find_first_subdir` 下降到子目录后丢失 login.jsp 等 | 从 extract root 打包，保留完整结构 |
| 缺少 V13/V13.5/V14/V15/V16 登录变体 | 只用母模板打一个登录包 | 新增 `LOGIN_VARIANTS` 映射，生成所有变体 |
| 版本命名错误 VV12/VV13_5 | `.replace("ekp_","V").upper()` 逻辑错 | 新增 `VERSION_LABELS` 字典 |
| 文本色值遗漏 | 只更新 variables，没更新 text content | `update-pen-theme.py` 硬编码模板默认值映射 |
| 渐变组件被清空 | 脚本匹配太宽泛 | 只更新 RWYIx/6U9v0 精确节点 |
| 背景图路径错误 | 相对路径 Pencil 找不到 | 绝对路径 |
| 登录包 CSS 不更新 | `find_first_subdir` 返回 `design-xml` 而非根 | 检查根目录是否有 `style/` |
| 找不到模板目录 | 目录名 `样例包` 但工具期望 `主题样例包` | 创建 symlink |
| manifest 路径错误 | 硬编码推断，目录改名不匹配 | 自动搜索多个候选路径 + 文件存在验证 |
