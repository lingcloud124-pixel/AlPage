## 2. 总体实施原则

实施过程中遵循以下原则：

### 原则 1：预览优先

先保证用户在 Web 端能看到稳定的主题预览，再扩展导出和打包。

### 原则 2：预览源 = 截图源

HTML 模板同时服务于：

- 用户预览
- Playwright 截图
- 打包素材生成

### 原则 3：结构代码化，复杂效果资产化

- 结构、布局、常规渐变：HTML/CSS 实现
- 难复刻特效：Pencil 导出设计资产

### 原则 4：先打通闭环，再做增强

优先完成：

```text
输入需求 → 主题渲染 → 预览 → 截图 → 打包
```

而不是先做大量锦上添花功能。

---

## 3. 实施阶段划分

建议分 6 个实施阶段：

| 阶段 | 目标 | 输出 |
|------|------|------|
| 阶段 0 | 基础稳定化 | 测试、构建、文档、约束统一 |
| 阶段 1 | 统一主题渲染模型 | ThemeRenderModel 与变量注入链路 |
| 阶段 2 | 模板预览完整化 | login / desktop / header / sidebar 模板稳定可预览 |
| 阶段 3 | 截图导出链路 | Playwright 截图 + 产物命名/尺寸稳定 |
| 阶段 4 | 打包闭环 | 主题包批量导出可用 |
| 阶段 5 | 增强能力 | 模板库、偏好记忆优化、视觉 QA、体验增强 |

---

## 4. 详细任务拆分

## 阶段 0：基础稳定化

### 目标

让项目具备持续开发能力，避免“边做边坏”。

### 任务包

#### 0.1 测试与构建稳定

- 修复根目录历史失败测试
- 保证 `npm run test:unit` 全绿
- 保证根目录 `npm run build` 通过
- 保证 `web/` 子项目构建通过

#### 0.2 文档体系建立

- 用户操作说明书
- PRD 流程文档
- 开发者系统流程图
- 专项技术方案
- docs 导航

#### 0.3 术语统一

- Theme Studio = Web 工作台
- Topic Automation = 项目名称
- 素材包 / 输出包 / 主题包术语统一

### 验收标准

- 测试通过
- 构建通过
- 文档可导航

---

## 阶段 1：统一主题渲染模型

### 目标

建立一个统一的主题渲染输入模型，避免颜色、图片、渐变在多个模块里零散传递。

### 任务包

#### 1.1 ThemeRenderModel 定义

- 定义颜色字段
- 定义图片字段
- 定义渐变字段
- 定义模板类型字段

#### 1.2 渲染输入适配层

- `colors/*.json` → ThemeRenderModel
- AI 工具输出 → ThemeRenderModel
- 预设卡片 → ThemeRenderModel

#### 1.3 注入层统一

- 颜色变量统一注入
- 图片变量统一注入
- 渐变变量统一注入

### 依赖

- 阶段 0 完成

### 验收标准

- 同一主题模型可驱动多个模板
- 不再在多个页面中零散写主题注入逻辑

---

## 阶段 2：模板预览完整化

### 目标

让 HTML 模板成为稳定的最终渲染源。

### 任务包

#### 2.1 登录页模板完善

- 密码 / 短信 / 扫码 交互
- 背景图和主题色联动
- 表单状态完整

#### 2.2 工作台模板完善

- header
- sidebar
- widgets
- 主题化视觉层

#### 2.3 页眉系列模板补全

- 60px header
- 90px header
- 130px header
- banner
- sideheader

#### 2.4 复杂效果分层实现

- 常规渐变用 CSS
- 难复刻效果抽离为资产
- 统一特效挂载方式

### 依赖

- ThemeRenderModel 已完成

### 验收标准

- 用户可稳定在 Web 中看到完整主题
- 模板视觉足以进入截图导出阶段

---

## 阶段 3：截图导出链路

### 目标

把预览结果变成稳定可复用的截图素材。

### 任务包

#### 3.1 截图映射表

- 模板 → selector → 输出文件名 → 尺寸
- 登录页映射
- 工作台映射
- 页眉映射

#### 3.2 Playwright 截图流程

- 固定尺寸渲染
- 统一等待条件
- 统一截图路径

#### 3.3 截图后处理

- resize
- crop
- rename
- 目录归档

#### 3.4 素材校验

- 文件存在性
- 尺寸校验
- 命名规范校验

### 依赖

- 模板已经完整可渲染

### 验收标准

- 能稳定生成素材包
- 生成结果与预览一致

---

## 阶段 4：打包闭环

### 目标

把素材包转成可交付主题包。

### 任务包

#### 4.1 打包请求生成

- 生成 YAML
- 生成 JSON
- 收集当前主题变量与素材路径

#### 4.2 多版本打包

- MK
- V12
- V13.5
- V14~V16
- V17

#### 4.3 打包验证

- 输出数量校验
- 颜色注入校验
- 历史归档逻辑

#### 4.4 Web 端导出体验

- 打包进度
- 结果提示
- 下载交互

### 依赖

- 素材导出链路稳定

### 验收标准

- 能从 Web 端完成完整主题包导出
- 输出包数量和内容符合规范

---

## 阶段 5：增强能力

### 目标

在闭环已经稳定的基础上继续提高体验与效率。

### 可选任务包

- 预设库搜索与筛选
- 用户偏好记忆增强
- 品牌色快速推导
- 图片主色推导增强
- 视觉 diff 校验
- 模板缩略图浏览
- 项目置顶 / 收藏 / 对比模式

### 验收标准

- 提升用户效率
- 不破坏导出主链路

---

## 5. 任务依赖关系

```text
阶段 0 基础稳定化
  ↓
阶段 1 统一主题渲染模型
  ↓
阶段 2 模板预览完整化
  ↓
阶段 3 截图导出链路
  ↓
阶段 4 打包闭环
  ↓
阶段 5 增强能力
```

## 6. 可并行任务建议

以下任务可以并行推进：

### 并行组 A

- 登录页模板完善
- 工作台模板完善
- 页眉模板补全

### 并行组 B

- 文档建设
- 测试补齐
- 导出映射表整理

### 并行组 C

- 渐变策略抽象
- 设计资产导出
- Playwright 截图脚本

## 7. 每阶段交付物清单

| 阶段 | 交付物 |
|------|--------|
| 阶段 0 | 稳定测试、构建、文档 |
| 阶段 1 | ThemeRenderModel、注入层 |
| 阶段 2 | 完整模板系统 |
| 阶段 3 | 素材包导出能力 |
| 阶段 4 | 可交付主题包 |
| 阶段 5 | 增强功能与效率工具 |

---

## 8. 执行建议

推荐执行节奏：

1. 每次只推进一个主阶段
2. 每个主阶段拆成可验证的小批次
3. 每个批次都必须有：
   - 可见产物
   - 对应测试
   - 清晰验收标准
