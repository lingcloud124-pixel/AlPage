# AlPage 端到端流程（当前有效版本）

> 当前只保留 **Path B：Web 浏览器流程**。  
> 旧的 Pencil / `.pen` 人工确认流程已经退出主链路，不再作为执行步骤。

---

## 1. 总流程

```text
售前输入客户需求（可上传资料）
→ 系统收集足够客户信息
→ 摘要确认
→ 生成 PortalPlan
→ 展示门户预览
→ 用户继续迭代（对话式编辑 / 配置式编辑）
→ 全屏查看
→ 保存 / 分享 / 再次进入编辑
→ 保存时自动静默沉淀行业案例
```

---

## 2. 阶段说明

### 阶段 1：输入需求

- 用户打开 AlPage
- 在对话区描述当前客户需求
- 可上传图片、Word、PDF 等辅助资料
- 系统按需继续补充收集必要信息

输出：

- 生成所需上下文建立
- 产品进入可创作状态
- 客户信息逐步沉淀

生成前至少要确认：

- 客户名称
- 客户行业
- 客户核心职能/业务特征
- 本次门户用途
- 希望突出哪些卡片或信息
- 品牌/视觉倾向

---

### 阶段 2：摘要确认

- 系统判断信息已经足够
- 系统输出摘要确认
- 用户确认系统理解无误

输出：

- 当前客户画像
- 当前门户结构理解
- 当前页面风格理解
- `PortalPlan` 生成依据

---

### 阶段 3：生成 PortalPlan

- 系统直接生成一份 `PortalPlan`
- 工作区展示由 `PortalPlan` 派生的门户预览界面

输出：

- 当前门户方案
  - 企业资料和行业上下文
  - 主题层
  - 工作区规则层
  - 卡片内容层
  - 编辑历史与最终门户状态

> 这里是系统首轮生成的完成点。  
> 后续是否继续调整，由用户决定。

---

### 阶段 4：迭代

用户可通过两种方式继续修改同一份 `PortalPlan`：

1. **对话式编辑**
   - 改页面方向
   - 改内容表达
   - 让系统继续改门户结构或风格

2. **配置式编辑**
   - 编辑主题层
   - 编辑工作区规则层
   - 调整卡片区域位置和大小
   - 编辑卡片内容层

规则：

- `PortalPlan` 是唯一事实源
- 谁最后修改，谁生效
- 对话区和配置面板互斥显示，避免界面拥挤
- 配置面板包含三个 tab：主题、工作区规则、卡片内容

---

### 阶段 5：查看与结果使用

- 用户觉得当前门户效果 OK
- 用户全屏查看生成后的门户
- 用户进入结果使用阶段：
  - 保存
  - 分享
  - 再次进入编辑

输出：

- 一个可被继续使用的门户成果
- 一个可被再次打开和继续编辑的 `PortalPlan`

---

### 阶段 6：行业案例沉淀

保存门户时，系统自动静默沉淀行业案例。

规则：

- 由“保存门户”动作触发
- 不在 UI 上额外提示用户
- 案例库第一版接入服务端 SQLite
- 案例库第一版按行业 + 关键词检索

案例记录建议包含：

- 客户名称
- 客户行业
- 企业介绍摘要
- 企业文化关键词
- 业务关键词
- 门户用途
- 采用的主题风格
- 工作区规则模式
- 卡片内容生成模式
- 最终 `PortalPlan` 快照
- 创建人
- 创建时间

---

## 3. 当前系统边界

### AI 负责

- 理解当前客户需求
- 在过程中补充收集必要客户信息
- 输出摘要确认
- 生成 `PortalPlan`
- 响应继续对话式修改
- 按行业 + 关键词参考历史案例

### 产品功能负责

- 工作区承载
- 门户预览
- 配置式三层编辑
- 全屏查看
- 保存、分享与再次进入编辑
- 保存门户时静默沉淀行业案例

---

## 4. 关于 Pencil / `.pen`

`.pen` 文件现在的角色只有：

- 设计参考
- 模板基准
- 特殊效果的参考来源

它们**不是**当前产品执行流程中的阻塞步骤，不需要：

- 打开 Pencil 人工确认后再继续
- 通过 Pencil MCP 导出作为主截图链路
- 依赖 `.pen` 作为最终渲染器

---

## 5. 当前执行原则

1. **创作起点 = 输入需求**
2. **核心产物 = PortalPlan**
3. **修改方式 = 对话式编辑 + 配置式编辑双通道**
4. **配置层级 = 主题层 + 工作区规则层 + 卡片内容层**
5. **全屏查看 = 结果确认入口**
6. **结果使用 = 可保存、可分享、可再次编辑**
7. **案例沉淀 = 保存门户时自动静默写入 SQLite 行业案例库**
