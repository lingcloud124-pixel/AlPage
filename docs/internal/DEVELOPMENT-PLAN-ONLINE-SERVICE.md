# Theme Studio 在线服务化开发计划

> 版本: v1.0  
> 日期: 2026-04-23  
> 目标: 从当前以本地导出为中心的实现，演进到“在线生成预览 + 服务端打包 + 在线下载”的产品形态

---

## 一、目标

本计划用于指导接下来的产品开发顺序。

核心目标：

- 保留当前在线生成与预览能力
- 去掉对本地桥接作为正式产品能力的依赖
- 建立服务端导出任务执行平台
- 支撑多用户同时使用
- 为测试和上线提供明确分阶段目标

---

## 二、开发原则

1. 先定产品边界，再改实现
2. 先做服务端闭环，再做体验优化
3. 打包输入必须基于确认态
4. 预览、截图、打包尽量共用同一份主题数据源
5. 每个阶段都要有可验证的测试出口

---

## 三、分阶段计划

### 阶段 1：产品与数据基线

目标：

- 确认在线服务产品边界
- 明确确认态、导出任务、下载结果的数据模型

任务：

- 定义项目模型、确认版本模型、导出任务模型
- 明确支持产品版本
- 明确任务状态集合
- 明确结果存储结构

产出：

- 产品定义文档
- 服务端任务状态机设计
- API 草案

---

### 阶段 2：服务端导出任务基础设施

目标：

- 能由服务端接收打包任务并管理状态

任务：

- 新增导出任务创建接口
- 新增任务查询接口
- 新增任务状态持久化
- 设计任务队列或异步执行机制

产出：

- 导出任务 API
- 导出任务持久化层
- 基础状态机

---

### 阶段 3：服务端截图与素材生成

目标：

- 把当前截图与素材准备能力迁移到服务端运行

任务：

- 服务端可启动预览渲染环境
- 服务端执行截图任务
- 服务端执行素材生成任务
- 保留当前导出基线约束

重点约束：

- 背景图来源和 HTML 预览截图来源不能混淆
- `素材包/` 与 `.build-meta/` 目录规则必须保持

产出：

- 服务端截图 worker
- 服务端素材生成链路
- 对应自动化测试

---

### 阶段 4：服务端标准打包与下载

目标：

- 服务端闭环完成打包、校验和结果下载

任务：

- 调用 `theme_builder.py`
- 调用 `verify-build.py`
- 存储打包结果
- 提供下载接口
- 支持历史结果重复下载

产出：

- 服务端打包 worker
- 下载接口
- 历史结果列表

---

### 阶段 5：前端产品闭环调整

目标：

- 前端完全对齐“在线服务”体验

任务：

- 将“打包”统一改为“生成主题包”
- 去除本地桥接依赖提示
- 增加确认版本入口
- 增加服务端任务状态展示
- 增加下载结果入口

产出：

- 新任务面板
- 新下载交互
- 新确认态交互

---

### 阶段 6：多用户与上线质量

目标：

- 满足首版可上线质量

任务：

- 完成用户隔离
- 完成并发任务验证
- 增加日志、告警、诊断能力
- 完成预发布环境回归

产出：

- 多用户隔离验证结果
- 并发测试结果
- 上线检查清单

---

## 四、建议开发顺序

建议严格按以下顺序推进：

1. 数据模型与任务状态机
2. 导出任务 API
3. 服务端截图能力
4. 服务端素材生成能力
5. 服务端打包与校验
6. 下载与历史记录
7. 前端交互改造
8. 多用户与稳定性收尾

不要反过来先改前端按钮文案或页面结构，否则会出现界面先承诺、后端还没接上的问题。

---

## 五、阶段验收门槛

### 阶段 1 完成标准

- 文档对齐
- 数据模型明确
- 状态机明确

### 阶段 2 完成标准

- 可创建任务
- 可查询状态

### 阶段 3 完成标准

- 服务端可生成截图和素材
- 导出基线测试通过

### 阶段 4 完成标准

- 服务端可生成可下载结果
- 打包和校验通过

### 阶段 5 完成标准

- 用户可以完整走通“生成 -> 确认 -> 打包 -> 下载”

### 阶段 6 完成标准

- 多用户隔离通过
- 并发稳定性通过
- 预发布回归通过

---

## 六、当前开发注意事项

在正式进入服务端化改造前，以下现有约束不能丢：

- 导出主链的唯一真相源
- 素材来源分类规则
- Light 三明治变量优先级
- `素材包/` 只放图片
- 打包标题 10 字符限制

参考文档：

- `docs/internal/IMPORTANT-EXPORT-INVARIANTS.md`
