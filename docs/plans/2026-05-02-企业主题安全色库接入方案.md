# 企业主题安全色库接入方案

## 目标

将“企业主题安全色库 + 语义映射 + Primary 禁区规则”接入当前主题生成链路，用于提升企业主题主色的稳定性、统一性和可用性。

目标不是替代全部图片取色，而是将当前“图片候选主色”升级为：

```text
用户语义 / 图片候选色
↓
企业安全色策略层
↓
输出稳定 primary
↓
Token 演算
```

## 当前项目现状

当前项目已经具备以下基础能力：

- `web/src/theme/color-utils.ts`
  - 主色禁区过滤
  - 候选色排序
  - primary 归一化
  - fallback 色盘
- `web/src/tools/executor.ts`
  - 从图片候选色中选主色
  - 已确认色相方向强制纠偏
- `web/src/tools/theme-intent-parser.ts`
  - 主题语义分类
- `web/src/agent/tool-call-utils.ts`
  - 用户颜色意图识别

当前缺口：

- 没有结构化的企业安全主色库
- 没有“主题语义 -> 企业安全主色”的稳定映射层
- 图片取色仍以像素候选色为主，语义策略只起辅助作用

## 设计原则

### 1. 不废弃图片取色

不采用：

```text
完全禁用图片取色
```

而采用：

```text
图片取色给出候选
语义策略层做纠偏
```

原因：

- 当前主图生成主题流程已建立
- 完全改为语义色库会让“按图定色”能力退化
- 更合理的是让图片色成为候选来源，而不是最终唯一来源

### 2. 语义高置信度时优先映射安全主色

当用户输入明确表达企业语义时，优先输出企业安全主色，不依赖图片自由取色。

示例：

- `现代科技未来办公平台` -> `#0E70EE`
- `生生不息 共筑未来` -> `#6A2500`
- `年度荣耀峰会` -> `#B56A1E`
- `红色党建文化宣传主题` -> `#C62828`

### 3. 安全色库是配置，不是散落代码

企业主色库、语义标签、行业标签、气质标签应作为独立配置存在，不能直接写死在算法函数内部。

### 文件 2：语义映射解析器

建议新增：

`web/src/theme/enterprise-primary-mapper.ts`

建议职责：

- 输入用户原始文本
- 输入 `theme-intent-parser` 的分类结果
- 输出最匹配的企业安全主色
- 返回命中原因和置信度

建议接口：

```ts
export interface EnterprisePrimaryMatch {
  presetHex: string;
  presetLabel: string;
  confidence: 'high' | 'medium' | 'low';
  matchedTags: string[];
  reason: string;
}

export function resolveEnterprisePrimaryFromText(
  text: string,
  context?: {
    category?: string;
    styleHints?: string[];
    colorHints?: string[];
  }
): EnterprisePrimaryMatch | null
```

### 文件 3：Primary 禁区规则扩展

继续放在：

`web/src/theme/color-utils.ts`

建议在现有基础上扩充：

- 粉色禁区
- 马卡龙禁区
- 荧光禁区
- 浅奶油禁区
- 企业橙色安全区

不要把这些规则写在多个文件中，避免主色合法性出现分叉。

## 推荐接入点

### 接入点 1：`resolvePreferredHueHint(...)`

现状：

- 只支持 `red / blue / green / pink` 这类粗粒度提示

建议：

- 保留原功能
- 新增“命中企业安全色库 preset 时，返回更强的 fallbackHex”

但这里不适合直接塞完整词库，因为这个函数本质还是“色相提示层”，不是“语义主色决策层”。

### 接入点 2：`pickBestThemeCandidate(...)`

这是主色选择的核心入口，最适合加“策略层决策”。

建议优先级：

1. 如果用户显式指定 hex -> 直接用用户值
2. 如果语义映射 `confidence = high` -> 直接用企业安全色
3. 如果语义映射 `confidence = medium` -> 对该 preset 色系强加分
4. 否则 -> 继续从图片候选色中选

建议新增参数：

```ts
semanticPrimaryHint?: {
  hex: string;
  confidence: 'high' | 'medium' | 'low';
}
```

### 接入点 3：聊天/生成链路

建议在调用 `generate_theme_pipeline` 或 `apply_selected_theme` 前，把用户语义先解析为企业安全主色提示。

优先文件：

- `web/src/agent/tool-call-utils.ts`
- `web/src/tools/executor.ts`

这样 AI 聊天场景里：

- 用户说“现代科技未来办公平台”
- 可以直接映射到 `#0E70EE`
- 不需要再让模型自由猜一个“蓝色系”

## 推荐算法分层

建议最终采用以下分层：

### 层 1：用户显式输入

优先级最高：

- `#6A2500`
- `改成深棕色`
- `用科技蓝`

如果用户明确提供了具体色值，例如：

- `主题色改成 #6A2500`
- `我想把主色换成 #0E70EE`

则必须优先使用用户提供的色值，不能被：

- 企业安全色库语义映射
- 图片候选色筛选
- fallback 色盘

覆盖。

推荐规则：

```text
explicit hex
>
enterprise semantic mapping
>
image candidate selection
```

说明：

- 显式 hex 属于用户明确决策，不应再被系统“优化成更安全的企业色”
- 企业安全色库只在用户未给出明确色值时介入
- 如果用户给的是颜色词而不是 hex，例如“深棕色”“科技蓝”，则仍可先走颜色语义或企业安全色库映射

### 层 2：语义映射

如果文本中能明确识别：

- 科技
- 金融
- 政务
- 峰会
- 企业文化
- 节庆

则优先映射到企业安全色库。

### 层 3：图片候选色

如果没有明确语义，再从图片里取候选色。

但候选色必须经过：

- 禁区过滤
- 企业安全色相加分
- 语义方向校正
- 对比度校验

## 最小落地版本

建议先做 V1，不一次做满：

### V1 范围

1. 新增企业安全色库配置文件
2. 新增语义主色映射函数
3. 在 `pickBestThemeCandidate(...)` 中支持语义高置信度直出 preset
4. 扩展禁区规则：
   - 粉色
   - 马卡龙
   - 荧光
   - 浅奶油
5. 为企业橙色建立安全区

### V1 不做

1. 不重写全部 theme-intent-parser
2. 不废弃图片取色
3. 不一次性把所有文案系统都改为“语义优先”
4. 不把所有品牌逻辑都塞进 prompt 层

## 风险与注意事项

### 1. 不能把“语义映射”做成绝对覆盖

如果用户上传了非常明确的品牌主图，而语义映射硬把主色改掉，可能造成视觉不一致。

因此建议：

- `high confidence` 才可直接替换
- `medium confidence` 只加分不替换

### 2. 不能让安全色库和现有 fallback 色盘分叉

当前已有：

- `STANDARD_FALLBACK_PALETTE`
- `resolvePreferredHueHint().fallbackHex`

企业安全色库接入后，这三处必须统一来源，避免同一语义在不同链路得到不同主色。

### 3. 不能在多个文件重复维护关键词

当前项目已有：

- `theme-intent-parser.ts`
- `theme-scene-planner.ts`
- `tool-call-utils.ts`

如果新词库直接重复写进去，后续会很难维护。

建议把企业语义词汇作为单独配置导出复用。

## 结论

这份“企业主题安全色库”非常适合接入当前项目，但不适合原样替换当前图片取色逻辑。

最合适的接法是：

```text
语义优先
图片候选辅助
安全色库定锚
禁区规则兜底
```

也就是：

```text
用户语义 / 图片候选色
↓
企业安全色策略层
↓
稳定 primary
↓
Token 演算
↓
主题包生成
```

这样可以同时保留：

- 当前项目已有的图片驱动能力
- 企业主题主色的稳定性和一致性
