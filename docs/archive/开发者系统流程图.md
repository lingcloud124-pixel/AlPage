## 1. 系统目标

Theme Studio 是主题自动化（Topic Automation）项目中的 Web 工作台，需要完成两类链路的协同：

1. **门户生成与编辑链路**：负责输入需求、生成新门户、预览、交互和结果使用
2. **底层渲染与素材链路**：负责支撑门户生成、HTML 预览和后续截图等技术能力

---

## 2. 顶层系统结构

```text
[用户输入]
    ↓
[Web UI]
    ├─ AI 对话
    ├─ 门户预览
    ├─ 工作区卡片编辑
    ├─ 全屏查看
    └─ 保存 / 分享入口
    ↓
[门户数据层]
    ├─ 当前门户状态
    ├─ localStorage 工作区数据
    ├─ 用户偏好
    └─ 页面内容 / 卡片配置
    ↓
[门户生成链路]
    ├─ 需求理解
    ├─ 门户结构生成
    ├─ 内容组织
    ├─ HTML 预览渲染
    └─ 工作区状态更新
    ↓
[输出产物]
    ├─ 新门户
    ├─ 全屏结果
    └─ 可保存 / 可分享 / 可再编辑状态
```

---

## 3. Web 运行流程

## 3.1 初始化流程

```text
DOMContentLoaded
→ 初始化颜色编辑器
→ 初始化工作区
→ 初始化默认工作区
→ 加载 localStorage 工作区状态
→ 加载用户偏好
→ 渲染欢迎消息
```

---

## 3.2 用户发送消息流程

```text
用户输入文本 / 图片
→ 写入 conversationHistory
→ 渲染用户消息
→ 调用 chatCompletion()
→ 解析 AI 回复
→ 解析 Tool Calls
→ 执行工具
→ 更新门户状态
→ 刷新门户预览
→ 渲染 AI 消息
```

---

## 3.3 工具执行流

当前典型工具包括：

### `generate_theme_pipeline`

```text
输入 用户描述
→ 生成背景图（MiniMax image-01）
→ 客户端 canvas 分析图片主色
→ deriveColorsFromPrimary() 计算完整配色
→ 组装门户视觉数据并驱动页面生成
```

### `update_colors`

```text
输入 colors
→ 更新 CSS 变量
→ 写入当前工作区状态
→ 触发预览刷新
```

### `validate_colors`

```text
输入当前配色
→ contrast-validator.ts WCAG 2.1 对比度校验
→ 输出校验报告
```

### `save_colors / load_colors`

```text
本地存储读写
→ 保持工作区结果可复用
```

---

## 3.4 预览联动流程

```text
颜色 / 图片 / 渐变更新
→ 写入 CSS 变量和图片变量
→ HTML 模板重新渲染
→ 门户界面实时变化
```

---

## 4. 门户生成链路

### AI 工作范围（Agent 负责）

```text
用户需求
→ 在过程中补充必要信息
→ 生成新门户
→ 实时应用到 HTML 预览
→ 用户继续修改
```

**输入**：用户描述、参考图（可选）、工作区上下文

**输出**：门户结构 + 页面内容 + HTML 预览状态

---

### 结果使用链路（产品功能）

```text
用户对当前门户满意
→ 全屏查看
→ 保存当前结果
→ 分享当前结果
→ 后续再次进入编辑
```

**输入**：当前门户状态

**输出**：可保存 / 可分享 / 可再次编辑的门户成果

---

### 历史说明：旧 Pen 文件流水线（已退出主链路）

> ⚠️ 以下流程已不再使用。当前系统通过 HTML 模板直接渲染，不再经过 Pencil .pen 文件。

- 旧阶段 2：Pen 文件更新 → 复制模板 .pen → update-pen-theme.py → 替换颜色/背景图 → Pencil 确认

- 旧阶段 3：素材导出 → Pencil MCP 导出节点 → ImageMagick 裁剪

## 6. 数据流

## 6.1 Web 数据流（AI 工作范围）

```text
用户消息
→ AI 回复
→ ToolCall（generate_theme_pipeline / update_colors）
→ 门户状态更新
→ 视觉变量注入
→ 当前工作区状态更新
→ localStorage 持久化
→ 右侧门户预览刷新
```

## 6.2 结果使用数据流（产品功能）

```text
当前门户状态
→ 全屏查看
→ 保存 / 分享动作
→ 可再次进入编辑的工作区记录
```

---

## 7. 关键门禁点

### 门禁 1：门户生成可用

如果系统还没有生成完整门户，不能把当前结果视为可继续编辑状态。

### 门禁 2：预览效果确认

用户在 Web 预览中确认满意后，才进入全屏查看和结果使用阶段。

### 门禁 3：结果使用可回流

如果用户保存或分享后无法再次回到可编辑状态，视为链路不完整。

---

## 8. 失败处理路径

```text
AI 输出不理想
→ 用户继续对话微调

预览效果不满意
→ 继续对话或直接编辑工作区卡片

结果不适合直接使用
→ 全屏退出后回到工作区继续调整
```

## 10. 架构结论

Theme Studio 的核心是 **AI 驱动的门户生成与编辑工作台**：

- **AI 负责生成与调整**：理解需求、生成新门户、持续迭代
- **产品负责承载与结果使用**：预览、直编、全屏、保存、分享、再次编辑
- **HTML 模板**是唯一渲染源，预览和截图共用
- **CSS 变量**驱动所有颜色，不硬编码
- **工作区状态持久化**（localStorage），用户可随时重新打开继续编辑

系统的核心设计原则：

> **输入需求后尽快生成一个新门户，并让用户围绕这个门户持续修改、确认和使用。**
