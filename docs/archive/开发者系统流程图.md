## 1. 系统目标

Theme Studio 是主题自动化（Topic Automation）项目中的 Web 工作台，需要完成两类链路的协同：

1. **Web 工作台链路**：负责对话、预览、交互、触发导出
2. **主题生产链路**：负责生成背景图、颜色方案、素材和最终主题包

---

## 2. 顶层系统结构

```text
[用户输入]
    ↓
[Web UI]
    ├─ 项目管理
    ├─ AI 对话
    ├─ 预设卡片
    ├─ 实时预览
    └─ 打包入口
    ↓
[主题数据层]
    ├─ 当前主题变量
    ├─ localStorage 项目数据
    ├─ 用户偏好
    └─ colors/*.json
    ↓
[主题生产链路]
    ├─ 背景图生成
    ├─ 颜色推导
    ├─ HTML 预览渲染
    ├─ 后台截图导出
    └─ 打包输出
    ↓
[输出产物]
    ├─ 素材包
    ├─ YAML / JSON
    └─ 多版本 zip
```

## 3. Web 运行流程

## 3.1 初始化流程

```text
DOMContentLoaded
→ 初始化颜色编辑器
→ 初始化项目侧边栏
→ 初始化默认工作区
→ 加载 localStorage 项目
→ 加载用户偏好
→ 渲染欢迎消息
```

---

## 3.2 用户发送消息流程

```text
用户输入文本 / 图片
→ 写入 conversationHistory
→ 渲染用户消息
→ 调用 chatCompletion()
→ 解析 AI 回复
→ 解析 Tool Calls
→ 执行工具
→ 更新主题变量
→ 刷新模板预览
→ 渲染 AI 消息
```

---

## 3.3 工具执行流

当前典型工具包括：

### `generate_theme_pipeline`

```text
输入 用户描述
→ 生成背景图（MiniMax image-01）
→ 客户端 canvas 分析图片主色
→ deriveColorsFromPrimary() 计算完整配色
→ 输出 21 个 CSS 变量 + 背景图 URL
```

### `update_colors`

```text
输入 colors
→ 更新 CSS 变量
→ 写入当前项目状态
→ 触发预览刷新
```

### `validate_colors`

```text
输入当前配色
→ contrast-validator.ts WCAG 2.1 对比度校验
→ 输出校验报告
```

### `save_colors / load_colors`

```text
本地存储读写
→ 保持方案可复用
```

---

## 3.4 预览联动流程

```text
颜色 / 图片 / 渐变更新
→ 写入 CSS 变量和图片变量
→ HTML 模板重新渲染
→ 登录页 / 工作台实时变化
```

## 4. 主题生产链路

### AI 工作范围（Agent 负责）

```text
用户需求
→ 生成背景图（MiniMax image-01）
→ 提取主色
→ 按 Light / Dark 规则推导主题色
→ 实时应用到 HTML 预览
→ 用户满意 → 保存项目（标准输出就绪）
```

**输入**：用户描述、参考图（可选）、模板类型

**输出**：色值库（21 个 CSS 变量）+ 背景图 URL + HTML 预览状态

---

### 导出链路（产品功能，Agent 不参与）

```text
用户选择产品和打包方式
→ 创建导出批次（当前项目快照 + 用户勾选产品）
→ 本地导出桥接层
→ Playwright 截图（login/desktop/header）
→ theme_builder.py 按需生成所选产品 zip
```

**输入**：色值库 + 背景图（来自 AI 工作的标准输出）

**输出**：`导出根目录/projects/{projectId}-{nameEn}/exports/{timestamp}/`

---

### 历史说明：旧 Pen 文件流水线（已退出主链路）

> ⚠️ 以下流程已不再使用。当前系统通过 HTML 模板直接渲染，不再经过 Pencil .pen 文件。

- 旧阶段 2：Pen 文件更新 → 复制模板 .pen → update-pen-theme.py → 替换颜色/背景图 → Pencil 确认

- 旧阶段 3：素材导出 → Pencil MCP 导出节点 → ImageMagick 裁剪

## 6. 数据流

## 6.1 Web 数据流（AI 工作范围）

```text
用户消息
→ AI 回复
→ ToolCall（generate_theme_pipeline / update_colors）
→ 主题变量更新（21 个 CSS 变量）
→ 背景图注入
→ 当前项目状态更新
→ localStorage 持久化
→ 右侧模板预览刷新
```

## 6.2 导出数据流（产品功能）

```text
色值库 + 背景图（标准输出）
→ 导出任务
→ 本地桥接层
→ Playwright 截图
→ theme_builder.py
→ zip 输出
```

---

## 7. 关键门禁点

### 门禁 1：配色规则校验

如果 Light / Dark 规则不满足，不能标记项目为完成。

### 门禁 2：预览效果确认

用户在 Web 预览中确认满意后，项目标准输出就绪。

### 门禁 3：打包输出校验（产品功能）

如果生成数量不对或颜色未注入，视为打包失败。
如果导出根目录未配置或桥接层不可用，导出批次状态应明确失败/待桥接。

---

## 8. 失败处理路径

```text
AI 输出不理想
→ 用户继续对话微调

预览效果不满意
→ 继续对话或手动调整颜色面板

打包失败（产品功能）
→ 修正配置或恢复桥接层后重新触发同一项目的新导出批次
```

## 10. 架构结论

Theme Studio 的核心是 **AI 辅助的主题设计器**：

- **AI 负责创意**：生图、配色、迭代调整（创建 + 迭代）
- **产品负责交付**：截图、打包、导出（按需触发）
- **HTML 模板**是唯一渲染源，预览和截图共用
- **CSS 变量**驱动所有颜色，不硬编码
- **项目持久化**（localStorage），用户可随时重新打开和打包
- **导出根目录由用户配置**，每次打包都是独立批次

系统的核心设计原则：

> **预览效果、导出素材、最终打包共享同一套主题数据源。Agent 工作到用户满意预览为止，之后的导出是产品功能。**
