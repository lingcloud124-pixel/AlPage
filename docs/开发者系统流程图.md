## 1. 系统目标

Theme Studio 是主题自动化（Topic Automation）项目中的 Web 工作台，需要完成两类链路的协同：

1. **Web 工作台链路**：负责对话、预览、交互、触发导出
2. **主题生产链路**：负责生成背景图、颜色方案、素材和最终主题包

---

## 2. 顶层系统结构

```text
[用户输入]
    ↓
[Web UI]
    ├─ 项目管理
    ├─ AI 对话
    ├─ 预设卡片
    ├─ 实时预览
    └─ 打包入口
    ↓
[主题数据层]
    ├─ 当前主题变量
    ├─ localStorage 项目数据
    ├─ 用户偏好
    └─ colors/*.json
    ↓
[主题生产链路]
    ├─ 背景图生成
    ├─ 颜色推导
    ├─ Pen 文件更新
    ├─ 素材导出
    └─ 打包输出
    ↓
[输出产物]
    ├─ 素材包
    ├─ YAML / JSON
    └─ 多版本 zip
```

---

## 3. Web 运行流程

## 3.1 初始化流程

```text
DOMContentLoaded
→ 初始化颜色编辑器
→ 初始化项目侧边栏
→ 初始化默认工作区
→ 加载 localStorage 项目
→ 加载用户偏好
→ 渲染欢迎消息
```

---

## 3.2 用户发送消息流程

```text
用户输入文本 / 图片
→ 写入 conversationHistory
→ 渲染用户消息
→ 调用 chatCompletion()
→ 解析 AI 回复
→ 解析 Tool Calls
→ 执行工具
→ 更新主题变量
→ 刷新模板预览
→ 渲染 AI 消息
```

---

## 3.3 工具执行流

当前典型工具包括：

### `update_colors`

```text
输入 colors
→ 更新 CSS 变量
→ 写入当前项目状态
→ 触发预览刷新
```

### `analyze_image`

```text
输入 imageUrl / dataUrl
→ 客户端 canvas 分析图片主色
→ 输出 dominantColors
```

### `parse_pen`

```text
输入 penContent / penPath
→ 解析 .pen 数据
→ 提取变量与结构信息
```

### `save_colors / load_colors`

```text
本地存储读写
→ 保持方案可复用
```

---

## 3.4 预览联动流程

```text
颜色 / 图片 / 渐变更新
→ 写入 CSS 变量和图片变量
→ HTML 模板重新渲染
→ 登录页 / 工作台实时变化
```

## 4. 主题生产链路（4 阶段）

## 阶段 1：背景图与配色

```text
用户需求
→ 生成背景图
→ 提取主色
→ 按 Light / Dark 规则推导主题色
→ 写入 colors/{nameEn}.json
```

### 输入

- 用户描述
- 参考图（可选）
- 模板类型

### 输出

- 背景图
- 配色 JSON

---

## 阶段 2：Pen 文件更新

```text
复制模板 .pen
→ update-pen-theme.py
→ 替换颜色变量
→ 替换背景图
→ 更新主题名称
→ 清理旧硬编码色值
→ Pencil 打开人工确认
```

### 输入

- 模板 `.pen`
- `colors/{nameEn}.json`
- 背景图

### 输出

- 新主题 `.pen`

### 关键门禁

- 用户在 Pencil 中确认视觉效果后，才能进入下一阶段

---

## 阶段 3：素材导出

```text
Pencil MCP 导出节点
→ ImageMagick / 脚本裁剪
→ 校验尺寸
→ 生成素材包目录
```

### 输入

- `.pen` 文件

### 输出

- `output/{date}-{nameEn}/素材包/`

---

## 阶段 4：批量打包

```text
生成 theme-build-request.yaml
→ 调用 theme_builder.py
→ 生成多版本 zip
→ verify-build.py 校验
```

### 输入

- 素材包
- YAML 配置
- 模板 zip

### 输出

- `output/{date}-{nameEn}/输出包/*.zip`

---

## 7. 关键门禁点

### 门禁 1：配色规则校验

如果 Light / Dark 规则不满足，不能进入下一步。

### 门禁 2：Pencil 设计确认

这是唯一人工确认门禁。

### 门禁 3：素材尺寸校验

如果导出文件缺失或尺寸错误，不能打包。

### 门禁 4：打包输出校验

如果生成数量不对或颜色未注入，视为失败。

---

## 8. 失败处理路径

```text
AI 输出不理想
→ 用户继续对话微调

Pencil 效果不满意
→ 回到 Pen 更新阶段修正

素材缺失 / 尺寸错误
→ 回到导出阶段重试

打包失败
→ 回到 YAML / 构建阶段修复
```

## 10. 架构结论

Theme Studio（作为主题自动化项目的 Web 层）本质上是一个 **AI 对话驱动的主题生产流水线**：

- 前台负责理解、交互、预览
- 中间层负责主题数据和变量
- 后台负责导出、裁剪、打包
- `.pen` 是中间设计稿
- `zip` 是最终交付物

系统的核心设计原则应该是：

> **预览效果、导出素材、最终打包尽可能共享同一套主题数据源。**
